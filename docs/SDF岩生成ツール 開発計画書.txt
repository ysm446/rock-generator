SDF岩生成ツール 開発計画書
1. 目的

Windows向けのスタンドアロン岩生成ツールを作る。
ZBrushのような破壊的スカルプトではなく、Houdini風の非破壊ノードベースで、SDF/VDBを中心に岩の形状・節理・亀裂・欠けを生成し、最終的にゲーム用メッシュとテクスチャを出力する。

2. 基本方針

制作中の内部表現は SDF / Volume。
最終出力は ゲームエンジン向けメッシュ + ベイク済みテクスチャ。

SDF生成
  ↓
亀裂・節理・破断
  ↓
SDFプレビュー / メッシュプレビュー
  ↓
高密度メッシュ生成
  ↓
LOD・UV・ベイク
  ↓
glTF / FBX / OBJ 出力
3. 推奨API構成
コア
Language: C++20
Build: CMake + vcpkg
Platform: Windows
UI / ノード
Dear ImGui
imgui-node-editor

Dear ImGuiはMITライセンスで、軽量なC++ GUIとして使いやすいです。
imgui-node-editor はDear ImGuiベースのノードエディタで、Blueprint系の複雑なノードUIの土台として使う目的のライブラリです。

描画 / GPU
DirectX 12
HLSL

Windows限定・ゲームデータ寄りならDirectX 12で良いです。Microsoftの説明でもDirect3D 12はDirectXの中核となる3D APIで、現代GPUを効率的に使うためのAPIとして位置づけられています。

Volume / SDF
OpenVDB
NanoVDB later

最初はCPU側でOpenVDB。
後でGPUプレビュー・高速サンプリング用にNanoVDB。

Mesh / Game Asset
meshoptimizer
xatlas
MikkTSpace
Assimp or tinygltf
OpenEXR / stb_image

目的：

Raymarch preview
Curvature / AO bake

NanoVDBはこの段階で検討。

9. Codexへの最初の依頼例

最初はこれくらい小さく切るのが良いです。

C++20 / CMake / Windows projectを作成してください。
Dear ImGui + DirectX 12 の基本ウィンドウを作り、
中央に3Dビューポート、左にノードエディタ領域、右にプロパティパネルを配置してください。
まだOpenVDBは使わず、ビューポートには回転するキューブを表示してください。

次：

OpenVDBを依存関係に追加し、
Sphere SDFを作成してメッシュ化し、
DirectX 12ビューポートに表示してください。

次：

imgui-node-editorを追加し、
Primitive SDF Node → Noise Warp Node → Volume To Mesh Node → Output Node
という固定グラフを作り、各ノードのパラメータをImGuiで編集できるようにしてください。

12. リスク
OpenVDB導入が重い

対策：

最初はOpenVDBなしでUI/Viewportを作る
次にOpenVDBを追加
DX12が重い

対策：

DX11で開始してもよい
ただし最終的にはDX12へ移行
亀裂が人工的になる

対策：

節理方向
複数スケール
岩種プリセット
ランダムではなくField制御
13. 最終的な理想像
RockForge / StoneGraph / Lithic

のような、岩専用ノードベース生成ツール。

中心コンセプト：

岩をスカルプトするのではなく、
節理・硬さ・亀裂・破断を積み重ねて生成する

最初の一歩は、DX12 + Dear ImGui + imgui-node-editorで空のアプリを作るところで十分です。
そこからOpenVDBを足すのが一番安全です。
